<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| GitHub Actions runner → repo checkout | Untrusted PR code executes workflow steps on hosted runner |
| Actions runner → GHCR | GITHUB_TOKEN crosses into package registry on push |
| Marketplace Actions → workflow | Third-party action tags resolve at runtime |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-01 | Elevation of Privilege | GITHUB_TOKEN permissions | mitigate | Explicit `permissions: contents: read` + `packages: write` only — no `contents: write`, no extra scopes (ASVS L1 access control) |
| T-04-02 | Tampering | Accidental PR image publish | mitigate | `push:` gated to `github.event_name == 'push' && github.ref == 'refs/heads/main'` (D-02, D-12) |
| T-04-03 | Tampering | Supply-chain action tag move | mitigate | Use official majors only (`actions/checkout@v7`, `astral-sh/setup-uv@v8`, `docker/*@v4|v6|v7`); no unverified third-party actions |
| T-04-04 | Information Disclosure | Public GHCR image contents | accept | Intentional per D-10; image has no secrets — public ResNet weights only; no PAT baked in |
| T-04-05 | Denial of Service | Unbounded CI runtime / cache miss | mitigate | Exclude docker/compose E2E (D-04); `type=gha,mode=max` + uv `enable-cache` (D-13, D-14); concurrency cancel-in-progress (D-03) |
| T-04-06 | Tampering | CUDA/wrong torch wheels in CI | mitigate | Two-step `--index-url` CPU torch install matching Dockerfile (D-07) |
| T-04-SC | Tampering | npm/pip/cargo installs in CI | accept | No new PyPI packages this phase; reuses pinned requirements; Actions from authoritative orgs only (Package Legitimacy Audit — no [SLOP]) |
</threat_model>
