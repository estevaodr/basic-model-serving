# Phase 1: Core Inference API - Research

**Researched:** 2026-07-07
**Domain:** FastAPI + PyTorch CPU inference API (greenfield)
**Confidence:** HIGH

## Summary

Phase 1 delivers a self-contained, locally runnable FastAPI service that loads ResNet-50 once at startup, serves top-5 ImageNet predictions via `POST /predict` (file upload or image URL), exposes split health probes, structured JSON logging, OpenAPI docs, and Prometheus metrics with the exact names required by MON-01. The repo is greenfield (LICENSE + stub README only); all application code is net-new following the layered structure in ARCHITECTURE.md.

The locked concurrency decisions (D-01 through D-04) drive several non-obvious implementation choices. Because `/predict` must be a plain `def` handler, URL fetching and file reads must use **synchronous** I/O (`UploadFile.file.read()`, `httpx.Client` or `requests`) — not `async def` with `await file.read()` or `httpx.AsyncClient`. PyTorch inference stays in the same sync handler and is offloaded to FastAPI's thread pool automatically [VERIFIED: Context7 `/websites/fastapi_tiangolo`]. Health and metrics endpoints should remain lightweight `async def` or `def` handlers that never call the model.

For MON-01, `prometheus-fastapi-instrumentator` defaults emit `http_requests_total` and `http_request_duration_seconds` [CITED: github.com/trallnag/prometheus-fastapi-instrumentator], which do **not** match the required metric names `request_count`, `request_duration`, `prediction_count`. Use `prometheus_client` directly with those exact names, wrapped in a thin Starlette middleware for request timing — simpler and requirement-accurate than renaming instrumentator defaults.

SSRF protection for the URL input path has no pinned third-party library in project research; implement a dedicated `url_fetch.py` module using stdlib `ipaddress` + `socket.getaddrinfo` + sync `httpx.Client(follow_redirects=False)` with IP pinning at connect time [CITED: cheatsheetseries.owasp.org/cheatsheets/Server_Side_Request_Forgery_Prevention_Cheat_Sheet.html]. DNS-rebinding is an accepted portfolio-scope limitation unless full transport-level pinning is implemented (recommended).

**Primary recommendation:** Build the layered FastAPI app per ARCHITECTURE.md with sync `/predict`, lifespan model load on `app.state`, dual content-type request contract (multipart for upload, JSON for URL), custom `prometheus_client` metrics with MON-01 names, and stdlib SSRF guards — then validate with pytest + `TestClient` before any container work.

### Locked Decisions

#### Concurrent Inference
- **D-01:** `/predict` is implemented as a plain `def` handler (not `async def`). FastAPI offloads synchronous CPU-bound PyTorch inference to its internal thread pool, keeping the asyncio event loop free for `/health/*` and `/metrics`.
- **D-02:** Single Uvicorn worker for Phase 1 — one process, one model copy in memory. Concurrent requests are handled via the thread pool within that process, not via multiple worker processes.
- **D-03:** No explicit concurrency cap (no semaphore/503 saturation gate). Rely on FastAPI/Uvicorn default thread pool behavior; sufficient for the portfolio demo target of 10+ concurrent requests.
- **D-04:** Configure `torch.set_num_threads()` at startup via env var (e.g. `TORCH_NUM_THREADS`, default sensible value like 2) through `pydantic-settings`. Avoids PyTorch defaulting to host CPU count, which causes cgroup throttling once deployed to Kubernetes in Phase 5.

### Pattern 1: Lifespan Model Load on `app.state`

**What:** Load ResNet-50 exactly once before accepting traffic; set `app.state.ready = False` until load completes.
**When to use:** API-06 — any expensive one-time initialization.
**Example:**

```python
# Source: https://fastapi.tiangolo.com/advanced/events
from contextlib import asynccontextmanager
from fastapi import FastAPI
import torch
from app.core.config import settings
from app.models.resnet import ResNetClassifier

@asynccontextmanager
async def lifespan(app: FastAPI):
    torch.set_num_threads(settings.torch_num_threads)
    app.state.ready = False
    app.state.classifier = ResNetClassifier()
    app.state.ready = True
    yield
    app.state.ready = False
    del app.state.classifier

app = FastAPI(lifespan=lifespan)
```

### Pattern 2: Dual Content-Type `/predict` Converging to One Pipeline

**What:** Single route handles two input modes; both normalize to `bytes` then share `inference.predict_from_bytes()`.
**When to use:** API-01 + API-02; HTTP forbids JSON + multipart in one request [CITED: fastapi.tiangolo.com/tutorial/request-forms-and-files].
**Recommended contract:**
- `Content-Type: multipart/form-data` with `file` field → upload path
- `Content-Type: application/json` with `{"image_url": "https://..."}` → URL path
- Route inspects `Content-Type` header or uses FastAPI dependency override

**Prescriptive recommendation:** Register **two plain `def` handlers on `/predict`**, both delegating to `services/inference.py`:

```python
# Source: https://fastapi.tiangolo.com/async + https://fastapi.tiangolo.com/tutorial/request-files
from fastapi import APIRouter, Depends, File, UploadFile
from app.schemas.prediction import PredictUrlRequest, PredictResponse

router = APIRouter()

@router.post("/predict", response_model=PredictResponse)
def predict_from_upload(file: UploadFile = File(...), classifier=Depends(get_classifier)):
    data = file.file.read()  # sync read — required in plain def
    return run_inference(data, classifier)

@router.post("/predict", response_model=PredictResponse)
def predict_from_url(payload: PredictUrlRequest, classifier=Depends(get_classifier)):
    data = fetch_image_url(payload.image_url)  # sync httpx.Client inside
    return run_inference(data, classifier)
```

FastAPI/Starlette can expose both operations on one path when content types differ. Verify `/docs` shows upload and JSON variants. **Fallback** if OpenAPI collision: single `multipart/form-data` endpoint with optional `file: UploadFile | None = File(None)` and `image_url: str | None = Form(None)` — one required, not both (Assumption A1).

### Pattern 3: Plain `def` for CPU-Bound Inference

**What:** Synchronous handler; FastAPI runs it in a thread pool [VERIFIED: Context7 `/websites/fastapi_tiangolo`].
**When to use:** D-01 — mandatory for `/predict`.
**Implications:**
- Use `file.file.read()` not `await file.read()`
- Use `httpx.Client()` not `AsyncClient`
- Use `torch.inference_mode()` context manager inside inference
- Health/metrics routes can stay `async def` (I/O-free, fast)

### Pattern 5: SSRF-Safe URL Fetch

**What:** Validate before connect; pin IP; no redirects.
**When to use:** API-05, PITFALLS.md Pitfall 8.
**Example:**

```python
# Source: https://cheatsheetseries.owasp.org/cheatsheets/Server_Side_Request_Forgery_Prevention_Cheat_Sheet.html
import ipaddress, socket
from urllib.parse import urlparse
import httpx

BLOCKED = lambda ip: (
    ip.is_private or ip.is_loopback or ip.is_link_local
    or ip.is_reserved or ip.is_multicast
)

def validate_url(url: str) -> None:
    parsed = urlparse(url)
    if parsed.scheme not in ("http", "https"):
        raise ValueError("Only http/https allowed")
    if not parsed.hostname:
        raise ValueError("Missing hostname")
    for family, _, _, _, addr in socket.getaddrinfo(parsed.hostname, parsed.port or (443 if parsed.scheme == "https" else 80)):
        if BLOCKED(ipaddress.ip_address(addr[0])):
            raise ValueError("URL resolves to blocked address")

def fetch_url_bytes(url: str, timeout: float, max_bytes: int) -> bytes:
    validate_url(url)
    with httpx.Client(timeout=timeout, follow_redirects=False) as client:
        with client.stream("GET", url) as resp:
            resp.raise_for_status()
            chunks, size = [], 0
            for chunk in resp.iter_bytes():
                size += len(chunk)
                if size > max_bytes:
                    raise ValueError("Response too large")
                chunks.append(chunk)
    return b"".join(chunks)
```

**Enhancement (recommended):** Pin connection to validated IP via custom transport (LangChain `SSRFSafeTransport` pattern [CITED: github.com/langchain-ai/langchain]) to close DNS-rebinding gap. Document as defense-in-depth, not blocking for Phase 1 MVP.

### Anti-Patterns to Avoid

- **`async def` + `model(tensor)`:** Blocks event loop — violates D-01 and Pitfall 1
- **`await file.read()` inside `def`:** Invalid; use `file.file.read()` [CITED: fastapi.tiangolo.com/tutorial/request-files]
- **Loading model per request:** Violates API-06 and <100ms target
- **Instrumentator defaults only:** Wrong metric names for MON-01
- **`Image.MAX_IMAGE_PIXELS = None`:** Decompression bomb risk [CITED: pillow.readthedocs.io/en/latest/handbook/security.html]
- **Trusting client Content-Type for uploads:** Verify via Pillow `Image.open()`, not filename extension

## Don't Hand-Roll

| Problem | Don't Build | Use Instead | Why |
|---------|-------------|-------------|-----|
| HTTP framework + validation | Custom Flask/bare Starlette | FastAPI 0.139 + Pydantic v2 | OpenAPI, validation, lifespan built-in |
| ResNet-50 weights + transforms | Manual weight download | `torchvision.models.resnet50(weights=ResNet50_Weights.IMAGENET1K_V2)` + `weights.transforms()` | Correct preprocessing tied to weights version |
| Prometheus text format | Custom /metrics serializer | `prometheus_client.generate_latest()` | Correct exposition format for scrapers |
| ImageNet label lookup | Hardcoded 1000-class list | `weights.meta["categories"]` | Stays in sync with weight version |
| Top-k softmax | Manual sort implementation | `prediction.topk(5)` + `softmax(0)` | Battle-tested tensor ops |
| Env-var config parsing | `os.environ.get()` scattered | `pydantic-settings` `BaseSettings` | Typed, validated, testable |

**Key insight:** The only area where hand-rolling is appropriate is SSRF URL validation — no pinned library in project stack, and stdlib `ipaddress` + `socket` meets API-05 without adding a dependency.

## Common Pitfalls

### Pitfall 1: Event Loop Blocking (PITFALLS.md #1)

**What goes wrong:** `async def` predict freezes `/health` under concurrent load.
**How to avoid:** Plain `def` on `/predict` (locked D-01).
**Warning signs:** Health latency spikes during predict traffic.

### Pitfall 2: PyTorch Thread Oversubscription (PITFALLS.md #2)

**What goes wrong:** Default threads = host CPU count; cgroup throttling in K8s later.
**How to avoid:** `torch.set_num_threads(settings.torch_num_threads)` in lifespan (locked D-04); default `2`.
**Warning signs:** Fine locally, degrades in container — Phase 5 concern, but wire env var now.

### Pitfall 3: Sync/Async I/O Mismatch in `def` Handler

**What goes wrong:** Using `await` or `AsyncClient` inside plain `def` causes runtime errors or blocking.
**How to avoid:** `file.file.read()`, `httpx.Client`, `requests.get` — all synchronous.
**Warning signs:** `RuntimeWarning: coroutine was never awaited`.

### Pitfall 4: OpenAPI / Request Contract Ambiguity

**What goes wrong:** Reviewer can't tell how to call `/predict` from `/docs`.
**How to avoid:** Document both input modes in route docstrings; provide `openapi_examples` for upload and URL variants.
**Warning signs:** `/docs` shows only one content type.

### Pitfall 5: MON-01 Metric Name Mismatch

**What goes wrong:** Grafana/Prometheus queries in Phase 3 reference `request_count` but app emits `http_requests_total`.
**How to avoid:** Use exact names from requirements, not instrumentator defaults.
**Warning signs:** `curl /metrics | grep request_count` returns nothing.

### Pitfall 6: Readiness Returns 200 Before Model Ready (PITFALLS.md #5)

**What goes wrong:** Traffic hits unloaded model; predict returns 500.
**How to avoid:** `/health/ready` checks `app.state.ready`; lifespan sets it only after successful load.
**Warning signs:** Ready=200 but first predict fails.

### Pitfall 7: SSRF via Redirect or Private IP (PITFALLS.md #8)

**What goes wrong:** `http://169.254.169.254/` succeeds.
**How to avoid:** Full checklist in Pattern 5; add tests rejecting loopback/metadata URLs.
**Warning signs:** No `url_fetch.py` module exists.

### Pitfall 8: Raw 500 on Bad Image (PITFALLS.md UX)

**What goes wrong:** `PIL.UnidentifiedImageError` becomes stack trace 500.
**How to avoid:** Catch decode errors → `HTTPException(400, detail={"error": "invalid_image", ...})`.
**Warning signs:** Uploading `.txt` as image returns 500.

## Code Examples

### ResNet-50 Load and Top-5 Predict

```python
# Source: https://github.com/pytorch/vision/blob/main/docs/source/models.md
import torch
from torchvision.models import resnet50, ResNet50_Weights

class ResNetClassifier:
    def __init__(self):
        self.weights = ResNet50_Weights.IMAGENET1K_V2
        self.model = resnet50(weights=self.weights)
        self.model.eval()
        self.preprocess = self.weights.transforms()
        self.categories = self.weights.meta["categories"]

    @torch.inference_mode()
    def predict(self, image) -> list[tuple[str, float]]:
        batch = self.preprocess(image).unsqueeze(0)
        probs = self.model(batch).squeeze(0).softmax(0)
        top5 = probs.topk(5)
        return [
            (self.categories[idx], float(probs[idx]))
            for idx in top5.indices.tolist()
        ]
```

### Request ID Middleware

import uuid, logging, contextvars
from starlette.middleware.base import BaseHTTPMiddleware

request_id_var: contextvars.ContextVar[str] = contextvars.ContextVar("request_id")

class RequestIdMiddleware(BaseHTTPMiddleware):
    async def dispatch(self, request, call_next):
        rid = request.headers.get("X-Request-ID", str(uuid.uuid4()))
        request_id_var.set(rid)
        response = await call_next(request)
        response.headers["X-Request-ID"] = rid
        return response

### Known Threat Patterns

| Pattern | STRIDE | Standard Mitigation |
|---------|--------|---------------------|
| SSRF via `image_url` | Spoofing | Scheme allowlist, IP denylist on resolved addresses, no redirect-follow, timeout+size cap [CITED: OWASP SSRF cheat sheet] |
| Decompression bomb | Denial of Service | Keep Pillow `MAX_IMAGE_PIXELS` default; reject oversized uploads before decode |
| Malicious file upload (non-image) | Tampering | Decode with Pillow; catch `UnidentifiedImageError` → 400 |
| Path traversal in filename | Information Disclosure | Ignore client filename for processing; don't write uploads to disk |
| Verbose 500 errors | Information Disclosure | Catch all inference/decode exceptions → structured 4xx/422; log details server-side only |
| Metric cardinality explosion | Denial of Service | Never label metrics with raw `image_url` or class name — `prediction_count` unlabeled or low-cardinality status only |
