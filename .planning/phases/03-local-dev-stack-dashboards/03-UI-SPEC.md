# Phase 3 — UI Design Contract

> Visual and interaction contract for the **Model Serving Overview** Grafana dashboard and unified alerting UI. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Scope:** This phase has no custom web frontend. The "UI" is Grafana 11.6.x (dark theme) provisioned as code under `monitoring/grafana/`. All contracts below apply to dashboard JSON, panel configuration, and alert rule presentation — not React components.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none (Grafana native) |
| Preset | not applicable |
| Component library | Grafana built-in panel types only |
| Icon library | Grafana Lucide icons (panel header icons only where useful) |

**Home dashboard (D-04):** Set `GF_DASHBOARDS_DEFAULT_HOME_DASHBOARD_PATH=/var/lib/grafana/dashboards/model-serving-overview.json`. Dashboard JSON must include `"uid": "model-serving-overview"`, `"title": "Model Serving Overview"`.

## Spacing Scale

Grafana uses a **24-column grid**. All panel widths and heights must use whole grid units (multiples of 1). Internal panel padding follows Grafana defaults — do not customize `fieldConfig` padding.

| Token | Grid value | Usage |
|-------|------------|-------|
| xs | 4 cols | Narrow stat panels (service up) |
| sm | 6 cols | Single stat panels (p50, p95, totals) |
| md | 8 cols | Medium time-series panels |
| lg | 12 cols | Half-width time series (request rate, throughput) |
| xl | 24 cols | Full-width breakdown panel (4xx vs 5xx) |
| row-gap | 1 grid unit | Vertical spacing between rows (Grafana default) |
| panel-h (stat) | 4 | Stat panel height — large enough for 38px value text |
| panel-h (timeseries) | 8 | Time-series panel height — readable legend + sparkline |

**Exceptions:** None. Do not use fractional grid widths.

## Typography

Panel text roles — configure via Grafana `fieldConfig.defaults` and panel options. Use Grafana defaults for font family; only specify sizes where the contract requires legibility for reviewer skim.

| Role | Size | Weight | Line Height | Where |
|------|------|--------|-------------|-------|
| Stat value | 38px | 500 (medium) | 1.0 | p50, p95, error rate %, service up, total predictions |
| Stat title | 14px | 400 (regular) | 1.2 | Panel title bar (Grafana default) |
| Time-series legend | 12px | 400 | 1.2 | Legend below/beside graphs |
| Axis label | 12px | 400 | 1.2 | Y-axis unit suffix only — no custom axis titles |
| Dashboard description | 14px | 400 | 1.5 | Dashboard-level description (one paragraph max) |

**Units display:**
- Latency stat panels: **milliseconds** (`unit: "ms"`) — convert from Prometheus seconds in PromQL or use Grafana unit transform
- Request rate / throughput: **requests per second** (`reqps`) or `ops` with suffix `/s`
- Error rate: **percent (0–100)** (`percentunit` or `percent` with 0–1 ratio)
- Total predictions: **short number** (`short`) — raw counter, no rate
- Service up: **none** — display `UP` / `DOWN` text mapping via value mappings (see Color section)

## Color

Grafana dark-theme semantic palette. Threshold colors drive reviewer-at-a-glance SLO reading — aligned with API-03 **<100ms** target and histogram buckets in `app/metrics/prometheus.py` (0.1s bucket boundary).

| Role | Hex / Grafana token | Usage |
|------|---------------------|-------|
| Dominant (60%) | `#181B1F` (Grafana dark canvas) | Dashboard background, empty chart areas |
| Secondary (30%) | `#22252B` (Grafana panel bg) | All panel surfaces |
| Accent — healthy | `#73BF69` (green) | Values within SLO; `up == 1`; 0% error rate |
| Accent — warning | `#FADE2A` (yellow) | Values approaching SLO breach |
| Accent — critical | `#F2495C` (red) | SLO breach; `up == 0`; elevated errors |
| Accent — informational | `#5794F2` (blue) | Secondary time-series line (4xx series in breakdown panel) |
| Destructive | `#F2495C` | Alert **Firing** state badge only |

**Accent reserved for:** threshold-driven stat values, service up/down indicator, alert rule state badges (Firing/Resolved), and the 5xx series line in the error breakdown panel. Do not use accent colors for panel borders, titles, or grid lines.

### Threshold contracts

#### Latency stat panels (p50, p95) — D-02

Metric: `histogram_quantile(..., rate(request_duration_bucket{path="/predict"}[5m]))`

| State | Condition (displayed ms) | Color |
|-------|--------------------------|-------|
| Healthy | `< 100` | Green `#73BF69` |
| Warning | `100 – 200` | Yellow `#FADE2A` |
| Critical | `> 200` | Red `#F2495C` |

Set `thresholds.mode: absolute`, `steps` base green → 100 yellow → 200 red.

#### Error rate stat panel

PromQL: `sum(rate(request_count_total{status=~"5.."}[5m])) / sum(rate(request_count_total[5m]))`

| State | Condition | Color |
|-------|-----------|-------|
| Healthy | `== 0` (or `< 0.001`) | Green |
| Warning | `0.001 – 0.01` (0.1%–1%) | Yellow |
| Critical | `> 0.01` (>1%) | Red |

Display as percentage with 2 decimal places.

#### Service up stat panel

PromQL: `up{job="app"}`

| Value | Display text | Color |
|-------|--------------|-------|
| `1` | `UP` | Green background on value |
| `0` | `DOWN` | Red background on value |

Use Grafana **value mappings** — not raw 0/1 numbers.

#### 4xx vs 5xx time-series panel — D-03

| Series | Color | Style |
|--------|-------|-------|
| 4xx rate | Blue `#5794F2` | Line width 2 |
| 5xx rate | Red `#F2495C` | Line width 2 |

No fill gradient. Legend: `4xx Errors`, `5xx Errors`.

## Dashboard Layout

**Dashboard:** `Model Serving Overview`  
**UID:** `model-serving-overview`  
**Tags:** `model-serving`, `portfolio`, `phase-3`  
**Timezone:** `browser`  
**Refresh:** `10s` (live demo feel; matches provisioning `updateIntervalSeconds`)  
**Time range default:** `Last 15 minutes`

### Panel inventory (8 panels — D-01)

Ops-standard grid: row 1 = traffic + latency headline stats; row 2 = rates + error trends; row 3 = health counters.

| # | Panel title | Type | Grid (x, y, w, h) | Description (panel subtitle) |
|---|-------------|------|-------------------|------------------------------|
| 1 | Request Rate | Time series | (0, 0, 12, 8) | HTTP requests per second across all routes |
| 2 | p50 Latency | Stat | (12, 0, 6, 4) | Median `/predict` response time (5m window) |
| 3 | p95 Latency | Stat | (18, 0, 6, 4) | 95th percentile `/predict` response time (5m window) |
| 4 | Error Rate | Stat | (12, 4, 12, 4) | Percentage of 5xx responses (5m window) |
| 5 | Prediction Throughput | Time series | (0, 8, 12, 8) | Predictions per second |
| 6 | HTTP Errors by Status | Time series | (12, 8, 12, 8) | 4xx vs 5xx error rates over time |
| 7 | Service Health | Stat | (0, 16, 6, 4) | Prometheus scrape target status |
| 8 | Total Predictions | Stat | (6, 16, 6, 4) | Cumulative successful predictions since startup |

**Binding rule:** Provision exactly **8 panel objects** in dashboard JSON. MON-02 requires 5–7 key metrics minimum; this set covers all D-01 metrics. Do not omit Service Health or Total Predictions.

### PromQL contract (from `app/metrics/prometheus.py`)

All queries filter route template paths where applicable — never raw URLs.

| Panel | PromQL |
|-------|--------|
| Request Rate | `sum(rate(request_count_total[5m]))` |
| p50 Latency | `histogram_quantile(0.50, sum by (le) (rate(request_duration_bucket{path="/predict"}[5m])))` |
| p95 Latency | `histogram_quantile(0.95, sum by (le) (rate(request_duration_bucket{path="/predict"}[5m])))` |
| Error Rate | `sum(rate(request_count_total{status=~"5.."}[5m])) / sum(rate(request_count_total[5m]))` |
| Prediction Throughput | `rate(prediction_count_total[5m])` |
| 4xx series | `sum(rate(request_count_total{status=~"4.."}[5m]))` |
| 5xx series | `sum(rate(request_count_total{status=~"5.."}[5m]))` |
| Service Health | `up{job="app"}` |
| Total Predictions | `prediction_count_total` |

**Datasource UID:** `prometheus` (must match provisioning).

### Panel type rules — D-02

| Metric category | Panel type | Rationale |
|-----------------|------------|-----------|
| p50, p95 | **Stat** (not time series) | Locked D-02 — single live number for reviewer skim |
| Error rate | **Stat** with thresholds | At-a-glance SLO signal |
| Service up, total predictions | **Stat** | Binary / counter snapshot |
| Request rate, throughput, 4xx/5xx | **Time series** | Trend visibility during curl demo |

Stat panels: enable **graph mode: none** (no sparkline) — pure number display per D-02.

Time series panels: **drawStyle line**, **fillOpacity 10**, **showPoints never**, **tooltip mode multi**.

### Empty / no-data states

Grafana shows native "No data" when Prometheus has no samples. Do not custom-style empty states.

| Context | Heading (native) | Body / next step (document in README, not on dashboard) |
|---------|------------------|-------------------------------------------------------------|
| No traffic yet | `No data` | Send sample requests: `curl -F "file=@tests/fixtures/sample.jpg" http://localhost:8000/predict` |
| Stack starting | `No data` (up to ~60s) | Wait for model load — `/health/ready` must pass before metrics appear |
| API stopped (demo) | Panels stale; Service Health → `DOWN` | Expected during alert demo — see README alert steps (D-10) |

### Error / alert copy

| Element | Copy |
|---------|------|
| Alert rule name | `Service Down` |
| Alert rule summary | `Model serving API is unreachable` |
| Alert rule description | `Prometheus cannot scrape app:8000/metrics for 1 minute. Check docker compose app service.` |
| Firing state label | `Firing` (Grafana native — do not rename) |
| Resolved state label | `Normal` (Grafana native) |
| Error state (misconfigured datasource) | README troubleshooting: verify Prometheus target `app` is UP at `:9090/targets` |

### Destructive actions

No destructive in-dashboard actions in Phase 3. Alert demo uses `docker compose stop app` from terminal (D-10) — not a Grafana UI action.

**Confirmation copy (README alert demo steps):**
1. `docker compose stop app`
2. Wait ~60–90 seconds
3. Open Grafana → Alerting → Alert rules → **Service Down** → state **Firing**
4. `docker compose start app`
5. Wait ~60 seconds → state **Normal**

## Alert Visualization (D-09, D-11, D-12)

| Property | Value |
|----------|-------|
| Engine | Grafana unified alerting (not Prometheus Alertmanager) |
| Provision path | `monitoring/grafana/provisioning/alerting/downtime.yml` |
| Query | `up{job="app"} == 0` |
| `for` duration | `1m` |
| Contact points | **None** (UI-only, D-12) |
| Notification policy | Default — no external receivers |
| Folder | `Model Serving` or default |
| Evaluation interval | Match Prometheus scrape: `15s` |

**UI expectations for reviewer demo (D-10):**
- Alert visible under **Alerting → Alert rules** without configuring contact points
- State transitions: **Normal → Firing** (red badge) → **Normal** (green badge)
- Do not provision silences, mute timings, or webhook contact points
- Alert list should show rule name **Service Down** with labels `severity=critical`, `team=model-serving` (optional, for filtering)

**Boot grace (D-11):** Alert must NOT fire during normal `docker compose up` startup. Infrastructure handles this via app healthcheck `start_period: 60s` + Prometheus `depends_on: service_healthy` — not via UI configuration.
